- **审查日期 (Date)**: 2026-10-10

- **重点审查模块**: `src/algo/ppo.h`, `src/algo/ppo.cpp`, `src/algo/rollout.h`, `src/algo/rollout.cpp`, `src/train.cpp`

---

## 摘要 (Executive Summary)

整体而言，本项目在 C++ 中非常出色地复现了 PerfectDou (NeurIPS 2022) 的核心思想（非完美信息 Actor + 完美信息 Critic 的 PTIE 框架，以及基于 ADP 回报的 PPO 自对弈训练）。底层数学推导（如 Softmax 策略梯度与动作掩码结合、GAE 优势计算、Adam 动量与范数裁剪）非常扎实，并且将历史动作序列通过固定步数 LSTM 展开成无状态特征，使得 Minibatch 随机打乱训练不仅高效而且不会破坏 RNN 隐藏状态。

然而，在深入代码审查后，我们发现当前强化学习算法设计中存在 **若干关键缺陷、逻辑不一致以及潜在的训练崩溃风险**，尤其是在多智能体合作对弈采样、值函数裁剪尺度、以及断点续训状态保持等方面。

## 详细审查分析 (Detailed Findings)

### 1. 致命逻辑缺陷：农民阵营在自对弈/联盟训练中的非一致性采样（"科学怪人"农民队友组合）
- **涉及代码**: `src/algo/rollout.cpp:205-225`
- **问题描述**:
  在 `runWorker` 中，每个对局的 3 个席位是**完全独立**掷骰子采样智能体类型的：
  ```cpp
  for (int s = 0; s < 3; ++s) {
      float r = float((dealRng.nextU64() >> 11) / double(1ULL << 53));
      if (r < cfg.ruleProb) {
          gameSeats[gi][s].type = PLAYER_RULE;
      } else if (hasHistPool && r < (cfg.ruleProb + cfg.historicalProb)) {
          gameSeats[gi][s].type = PLAYER_HISTORICAL;
          gameSeats[gi][s].histRef = gameHistRef;
      } else {
          gameSeats[gi][s].type = PLAYER_LATEST;
      }
  }
  ```
  在斗地主博弈中，地主（Seat 0）是独立一方，而下家农民（Seat 1）与上家农民（Seat 2）是紧密合作的团队，**共享最终胜负收益（ADP）**。
  独立随机采样导致在约 **42%** 包含联盟/规则 Agent 的对局中，出现**一个农民为最新的神经网络（`PLAYER_LATEST`），而其队友农民为启发式规则 Agent（`PLAYER_RULE`）或陈旧的历史快照（`PLAYER_HISTORICAL`）**！
- **算法危害**:
  1. **信用分配灾难**: 当 `PLAYER_RULE` 队友因规则局限性打出臭牌导致对局输掉时，`PLAYER_LATEST` 农民也会承担巨额负奖励（$-2$ 甚至 $-16$），通过 PPO 惩罚最新网络在该局中的所有合理出牌。
  2. **代码意图矛盾**: 代码在 183 行明确写有注释：
     `// Pre-sample a single historical snapshot for this game so that if both peasants are historical players, they come from the exact same version and cooperate consistently.`
     作者显然意识到两农民策略必须同源才能有效配合，但由于外层类型判断是独立循环执行的，导致“只有当两个农民碰巧都被抽中为历史模型时”才共享版本，未能保证“两农民属于同一智能体阵营”。
- **改进建议**:
  采样应以**阵营 (Camp)** 为单位进行：
  - 地主阵营（Seat 0）：独立采样类型（Latest / Historical / Rule）。
  - 农民阵营（Seat 1 和 Seat 2）：**作为一个整体统一采样**。要么双农民同为 `PLAYER_LATEST`，要么同为同一个历史快照 `PLAYER_HISTORICAL`，要么同为 `PLAYER_RULE`。

### 2. 算法设计冲突：固定 Value Loss Clipping (`vfClip=5.0`) 与斗地主炸弹翻倍指数收益尺度的冲突
- **涉及代码**: `src/algo/ppo.h:14`, `src/algo/ppo.cpp:392-412`
- **问题描述**:
  代码默认启用了 PPO 的值函数裁剪（`cfg.clipVf = true`，`cfg.vfClip = 5.0f`）：
  ```cpp
  float vOld = mb[i]->value;
  float vClipped = vOld + std::clamp(vPred - vOld, -cfg.vfClip, cfg.vfClip);
  float errClipped = vClipped - vTarget;
  float l1 = err * err;
  float l2 = errClipped * errClipped;
  if (l2 > l1) {
      vLossSum += 0.5 * l2;
      dValue.row(i)[0] = 0.0f; // 梯度被直接置零！
  }
  ```
- **算法危害**:
  1. 斗地主的结算分是底分乘以 $2^{\text{bombCount}}$（$-64 \sim +64$）。当单局出现 2~4 个炸弹时，真实回报会瞬间爆发到 $\pm 8, \pm 16, \pm 32$。
  2. 若当前 Critic 预测值 $V_{old} \approx 2.0$，真实回报为 $16.0$。当 $V_{pred}$ 朝真实回报方向大幅更新并超过 $V_{old} + 5.0 = 7.0$ 时，由于 $V_{clipped}$ 被卡在 $7.0$，必然有 $(7.0 - 16)^2 > (V_{pred} - 16)^2$，导致 $l_2 > l_1$。
  3. 此时 $dValue$ 会被立即置为 $0.0$，**彻底锁死 Critic 在该更新轮次中向高炸弹目标拟合的梯度**！
  4. 强化学习顶会经典文献（Engstrom et al., ICLR 2020: *Implementation Matters in Deep Policy Gradients*）已证实，PPO Value Clipping 经常抑制价值学习；在斗地主这种具有指数级长尾收益的环境中，固定数值剪切的问题尤为严重。
- **改进建议**:
  - 在高动态范围回报环境下，建议默认关闭 Value Clipping（使用 `--no-clip-vf`）；
  - 或者使用针对收益尺度的自适应阈值，或将 Critic 目标进行 Running 标准化后再计算剪切。

### 3. 工程与算法结合隐患：断点续训（`--resume`）重置优化器状态、退火调度与联盟池
- **涉及代码**: `src/train.cpp:207-212`, `src/train.cpp:325-338`, `src/train.cpp:254-295`
- **问题描述**:
  当使用 `--resume <path>` 恢复训练时：
  1. 代码仅加载了 Actor 和 Critic 的参数权重 `w`；
  2. Adam 优化器的一阶矩 $m$、二阶矩 $v$ 以及时间步数 $t$ 被完全丢弃并重置为 0；
  3. 学习率余弦衰减和熵系数衰减基于当前 `progress = (upd - 1) / (updates - 1)` 计算，导致续训时学习率立即跳回初始峰值（`3e-4`），熵系数也跳回最大值；
  4. 历史模型池（`HistoricalPool`）从空列表重新开始，在随后的几轮对局中无法提供历史对手对抗。
- **算法危害**:
  一个已经训练数十万步、已收敛至精细策略的模型，在断点续训时突然遭遇：**空动量冲击 + 峰值大步长学习率 + 最大随机探索熵惩罚 + 缺乏历史对手正则化**，极易诱发严重的**策略崩溃（Catastrophic Policy Collapse）**。
- **改进建议**:
  保存 Checkpoint 时应将 Adam 优化器状态（$m, v, t$）、当前全局 update 步数、退火进度以及历史联盟模型列表一同持久化保存并在 resume 时恢复。

---

### 4. 死代码与量纲失配：未使用的 `RunningNormalizer` 与未标准化的 Critic 目标
- **涉及代码**: `src/algo/ppo.h:40-64`, `src/algo/ppo.cpp:133-139`
- **问题描述**:
  `ppo.h` 完整实现了基于 Welford 算法的动态均值与方差归一化器 `RunningNormalizer`，并在 `tests/test_algo.cpp` 中通过了测试，但它在整个 `src/` 中**从未被任何代码调用**。
- **算法危害**:
  - Actor 的 Advantage 在整个 Batch 上执行了标准化（均值 0，方差 1），因此 Actor 的损失尺度受到良好约束。
  - 但 Critic 的目标值 $R$（`mb[i]->ret`）使用的是未经标准化的原始 ADP 标量（$-64 \sim +64$）。
  - Actor 和 Critic 使用了完全相同的学习率衰减逻辑（`aOpt.lr = cOpt.lr`）。虽然 Critic 单独设置了较大的梯度裁剪阈值 `criticMaxGradNorm = 5.0f`，但缺少对 Critic 回报的 Running 归一化使得 Critic 的梯度震荡显著高于 Actor。

---

### 5. 训练可观测性偏差：日志输出的胜率/ADP 受联盟对手污染
- **涉及代码**: `src/algo/rollout.cpp:353-358`, `src/train.cpp:680-682`
- **问题描述**:
  每轮 update 打印的 `WP`（地主胜率）和 `ADP` 是在包含 20% 历史模型、10% 规则模型以及两农民混合不对称对局的所有混合对局上统计的。
- **算法危害**:
  该数值不是最新版本地主对阵最新版本农民的纯自对弈胜率，无法真实反映最新策略的绝对自弈均衡演进趋势。一旦混入弱规则智能体，胜率和 ADP 会产生虚假漂移。建议在 Rollout 中拆分纯自对弈（Pure Self-Play）与联盟混合博弈（League Play）的统计指标。

## 算法实现优秀细节 (Strengths & Verified Components)

在严谨的审查中，我们也确认了以下核心强化学习组件实现高度规范、正确无误：

1. **精确的策略梯度推导与动作掩码处理**:
   在 `ppo.cpp:368-381` 中，对 Softmax 策略分布关于 Logits 的导数推导完全精确。`probs[a] * (W - sumW)` 精确对应 $\frac{\partial L}{\partial z_a}$，且当某动作概率为 1（强制唯一出牌/Pass）时，梯度自然为零，不产生寄生梯度。
2. **LSTM 局部无状态展开机制**:
   网络结构中虽然包含 10 步 LSTM，但它是对每个样本自带的 30 步历史动作局部执行前向。由于每个 Transition 自包含完整的历史，Minibatch 随机打乱（Shuffle）完全不破坏 RNN 时序性，兼顾了时序特征提取与训练数据独立同分布（IID）假设。
3. **GAE 倒序推导严谨**:
   `assignEpisodeReturns` 按照 `gameId` 倒序递推，当 $\gamma=1.0, \lambda=1.0$ 时严格等价于全 Monte Carlo ADP 回报；在 $\gamma=1.0, \lambda=0.95$ 时，平滑了中间值函数方差。
4. **Schulman $k_3$ 近似 KL 散度与早停机制**:
   计算的 `approxKL = (ratio - 1.0f) - logRatio` 保证非负且为真实 KL 的二阶一致估计；在每轮 Epoch 结束时对比 `1.5 * targetKL` 进行提前终止，有效防止策略更新步长越界。

## 对先前审查（Antigravity / Gemini 3.8 Flash）的评议

总体评价：前一份报告抓到的主线是对的，代码引用与机制描述大体准确，优先级排序也合理。下面按条目给出同意 / 修正 / 补充。

### 对 Finding 1（农民阵营非一致性采样）——同意，且可再钉死一点
- **同意**：`rollout.cpp:205-215` 确实对三个座位独立掷骰；注释只保证「双方都抽到历史模型时共用同一 snapshot」，**并不保证两农民类型一致**。
- **42% 数字核对**：在默认 `ruleProb=0.1, historicalProb=0.2`（其余 0.7 为 Latest）下，
  `P(一农民 Latest 且另一农民非 Latest) = 2 × 0.7 × 0.3 = 0.42`，计算正确。这正是「最新策略农民与异质队友共担 ADP」的有害情形。
- **额外加重因素**：`216-225` 的「每局至少一个 `PLAYER_LATEST`」兜底，可能把本已同质的双规则/双历史农民中的一人强行改成 Latest，**主动制造**不对称队友。
- **文档矛盾**：`README.md` 写「单局保证农民策略一致性」，与实现不符，属于误导性文档。
- **严重性微调**：这是联赛增强引入的设计缺陷，不是 PPO 数学错误；但对农民合作信用分配伤害真实存在。按阵营采样的修复建议正确，应维持 **P0**。

### 对 Finding 2（`vfClip=5.0` 与炸弹指数收益）——方向正确，措辞略偏重
- **同意机制分析**：`ppo.cpp:392-412` 在 `l2 > l1` 时把 `dValue` 置零，是标准 clipped value loss 的饱和区；目标远大于 `vOld + vfClip`（如 `vOld≈2, target=16`）时，朝目标大步更新会被截断。
- **严重性微调**：这不是「Critic 被永久锁死」。跨 update 后 rollout 的 `vOld` 会随 Critic 变强而抬高，价值可缓慢爬升；真正伤害是**稀有高炸弹局的样本效率**和**单次 update 内对尾部分布的拟合能力**。README 宣称 `vfClip=5.0`「与 ADP 尺度相匹配」也不准确——无炸弹局 `|R|∈{1,2}` 时尚可，多层炸弹后 `|R|` 可达十几到几十。
- **建议**：维持高优先级；更稳妥默认是 `--no-clip-vf`，或按回报 RMS / bomb 分位做自适应阈值，而不是口头把 5.0 说成「匹配 ADP」。

### 对 Finding 3（`--resume` 丢优化器与调度状态）——完全同意
- 代码仅 `load` 权重（`train.cpp:209-212`）；Adam `m/v/t`、余弦 `progress`、历史池均从零开始。
- 对已收敛策略续训，这是真实的崩溃风险，**P1** 成立。补充：即使保存了 Adam，若 `progress` 仍按「本次数组 `updates`」从 0 计，学习率仍会跳回峰值，续训协议需要「全局 update 计数」或显式 `--resume-from-update`。

### 对 Finding 4（`RunningNormalizer` 死代码）——同意现象，略降算法危言
- 死代码与 Critic 用原始 ADP 目标均为事实；Advantage 已按 batch 标准化也是事实。
- 论文公开设定也未要求 Critic 做 running return norm；更大的尺度问题其实与 Finding 2（value clip）耦合。保留为 **P2** 合理，但单独启用 normalizer 不是银弹。

### 对 Finding 5（WP/ADP 日志被联盟污染）——同意，属可观测性
- 不影响梯度正确性，但会误导调参。建议拆分 pure self-play / league 指标，同意。

### 对「优秀细节」一节——基本同意
- Softmax+掩码反传、`approxKL=(r-1)-log r`、按 `gameId` 倒序 GAE、LSTM 局部展开以支持 shuffle：复核后认为实现正确。
- 小补充：`chooseAction` 对全动作维做 `exp`，依赖非法 logit≈`-1e9`（ragged scatter 填入），实践上等价掩码，可接受。

## 本轮新发现 (Additional Findings)

### A. 致命论文对齐缺口：未实现 PerfectDou Sec. 4.4 的 Oracle 中间奖励
- **涉及代码**: `src/ddz/oracle.{h,cpp}`（已实现 `minSteps`）、`src/ddz/features.cpp`（Critic 特征用了 min-steps）、`src/ddz/game.cpp:67-77`（仅终局牌数 shaping）、`src/algo/rollout.cpp:363`（奖励 = `payoff + shaping`）、`src/train.cpp:8` 注释声称 `pure terminal ADP reward (paper aligned)`
- **问题描述**:
  论文主训练阶段明确使用 **ADP + Oracle 节点奖励**：
  `Adv_t = N_landlord - min(N_p1, N_p2)`，
  `r_t = ±(Adv_t - Adv_{t-1}) * l`（地主 −1.0×，农民 +0.5×），
  且该信号在**逐步/逐节点**给出，并用 `min(N_p1,N_p2)` 显式激励农民协作；仅最终微调阶段才去掉 oracle、纯 ADP。
  本仓库虽实现了 oracle DP，却**只喂给 Critic 特征**，奖励路径完全没用它；现有 `shaping()` 是终局牌数启发式（默认 cap=0.05），与论文公式无关。
- **算法危害**:
  1. 丢失论文消融中证明关键的 dense reward（RewardlessDou 在 ADP 上明显变差）。
  2. 农民协作本可由 `min(N_p1,N_p2)` 塑造，现在却依赖稀疏终局 ADP + 不对称联赛队友（Finding 1），协作更难学。
  3. `train.cpp` / 部分 README 表述「paper aligned」不成立，容易让后续复现者误判已对齐。
- **改进建议**:
  - 在 rollout 每步（或每节点）用 `minSteps` 计算 `Adv_t` 差分写入 `Transition.reward`，终局再叠加 ADP；提供 `--oracle-reward / --no-oracle-reward` 以支持论文所述两阶段训练。
  - 修正注释与 README，区分「特征用了 oracle」与「奖励用了 oracle」。

### B. 终局奖励只挂在「该座位最后一次决策」上（可接受，但需知情）
- 非终局 transition 的 `reward` 恒为 0，终局时给三家各自 `lastIdx` 写入 `payoff+shaping`。
- 在 `γ=1, λ=1` 下 GAE 退化为对该座位轨迹的蒙特卡洛 ADP，数学自洽；`λ=0.95` 时依赖同座位下一步价值自举，这是回合制多智能体常见做法，**不是 bug**。
- 但若补上 Finding A 的逐步 oracle 奖励，必须改为逐步写 `reward`，不能再只改 last transition。

### C. 联赛是工程增强，论文原始设定是「对最新对手自对弈」
- 论文附录 D.1：三座位模型「only updated by their own data against the latest opponent model」。
- 本仓库的 historical/rule 混合是合理的抗循环增强，但与 Finding 1 叠加后，偏离论文设定的代价被放大。修复阵营一致性后，联赛仍可保留。

## 综合结论

## 一、对前三份审查的评议

### 1.1 Finding #1（农民异质采样）——同意 P0，但 42% 这个数字**低估**了

Gemini 算的是 `2 × 0.7 × 0.3 = 0.42`，这只覆盖了"一个农民 Latest、另一个非 Latest"。遗漏的情形是 **"历史快照 vs 规则智能体"**（`2 × 0.2 × 0.1 = 0.04`），这一样是异质队友。

正确的异构概率应是：

```
P(两农民异质) = 1 - (0.7² + 0.2² + 0.1²) = 1 - (0.49 + 0.04 + 0.01) = 0.46
```

即 **46%**，而非 42%。再叠加 `rollout.cpp:216-225` 的 `anyLatest` 兜底（在没人抽到 Latest 时随机把某一席改成 Latest），实际比例还要**略高一点**。

结论不变，仍是 **P0**，修复建议（按阵营采样，农民两席同类型且同 `histRef`）我也认同。

补充一个三方都没点破的点：**即使两个农民都抽到 `PLAYER_HISTORICAL` 且共享同一 `histRef`，它们仍是"同一份旧网络的两个副本对打同一阵营"**,而 `PLAYER_LATEST` 农民的对手却可能是 Latest 地主。也就是说"席位类型组合"一共有 3×3（农民阵营内部）×3（地主）种联合分布，训练数据分布是被这个组合严重混淆的。修复时建议明确记录每种组合的占比以便做分层统计。

### 1.2 Finding #2（`vfClip=5.0`）——机制同意，但前审都没做量纲分析，我在 N1 里补齐

Composer 和 Copilot 已经把"不是永久锁死"讲清楚了，我同意。但三份报告都说"5.0 与 ADP 尺度不匹配"却没说到底差多少、以及为什么"不匹配"这件事比表面更严重。真正的结构性问题是：**这一个常数同时施加给了收益量纲相差 2 倍的两个角色**。详见 N1。

### 1.3 Finding #3（`--resume`）——同意 P1，但有一处前审的措辞需要修正

前审表述容易让人以为 `load()` 本身有 bug。**实际没有**：`net.cpp:417-430`（Actor）与 `net.cpp:518-531`（Critic）都做了 `init` → `loadParams` → `prepareInference()`，转置权重（`wt` / `wTi` / `wTh`）是会被正确重建的，不存在"推理用的是随机初始化核"这类问题。

## 二、本轮新发现

### N1 【P1】`vfClip` 是绝对阈值，但斗地主三个角色的收益量纲天生是 2:1

- **涉及代码**: `src/ddz/game.cpp:79-85`、`src/algo/ppo.h:14`、`src/algo/ppo.cpp:392-412`
- **问题描述**:

  `payoff` 是不对称的：

  ```cpp
  if (seat == kLandlord) return landlordWins ?  2.0 * mult : -2.0 * mult;
  return                  landlordWins ? -mult       :  mult;
  ```

  即 **地主 ADP = ±2·2^bombs，农民 ADP = ∓1·2^bombs**。（顺带确认这是零和的：2m − m − m = 0，采样约定正确。）

  后果是三个 Critic 虽然共享同一个网络宽度、同一个 `lr`、同一个 `vfCoef=0.5`、同一个 `criticMaxGradNorm=5.0`，它们的**目标值动态范围却相差 2 倍**。而 `vfClip=5.0` 是一个**绝对**阈值：

  | | 无炸弹 | 1 炸弹 | 2 炸弹 | 3 炸弹 | 4 炸弹 |
  | :--- | :---: | :---: | :---: | :---: | :---: |
  | 地主 target | ±2 | ±4 | ±8 | ±16 | ±32 |
  | 农民 target | ∓1 | ∓2 | ∓4 | ∓8 | ∓16 |

  于是同一个 `±5.0` 的窗口：

  - 对**农民**：要 3 个炸弹（|R|=8）才会让"从 0 直接拟合到 target"越出窗口；
  - 对**地主**：**只要 2 个炸弹（|R|=8）就同样越界；而 1 个炸弹（±4）加上一点点 bootstrap 误差就已经贴边**。

  换句话说，**这个常数对地主 Critic 的约束强度是对农民的约 2 倍**，地主的 Critic 会更早、更频繁地进入 `l2 > l1 → dValue = 0` 这个梯度为零的饱和区（`ppo.cpp:401-403`）。

- **算法危害**: 高炸弹局是 ADP 分布的长尾，也是农民/地主价值差异最剧烈的样本。当前配置让**动态范围更大的那一方被裁得更狠**，这是纯粹的副作用,不对应任何设计意图。
- **改进建议**（按推荐度排序）:
  1. 把 `vfClip` 改成**相对量**：`vfClip = k · running_std(returns)`，或直接用一个大得多的值（如 32）让它在正常局里永远不触发。
  2. 或者**给每个角色一套独立的 `vfClip`**，按各自 `payoff` 的基础倍率缩放（地主 2×农民）。
  3. 最省事：默认 `--no-clip-vf`，并把 `ppo.h:14` 那句 "ADP returns span roughly +-2..48" 的注释和 README:25/77 的"与斗地主 ADP 回报尺度相匹配"一并改掉——这句在 2:1 量纲面前是不成立的。

### N2 【P1】λ=0.95 下，所谓"pure terminal ADP target"在数学上并不成立

- **涉及代码**: `src/algo/ppo.cpp:20-43`、`src/train.cpp:8`
- **问题描述**:

  由于所有非终局转移的 `reward` 恒为 0，只有终局写入 `payoff + shaping`（`rollout.cpp:363`），GAE 可以解析展开。由 `ppo.cpp:37-40`：

  ```
  δ_t    = V(s_{t+1}) − V(s_t)                     (非终局)
  gae_t  = δ_t + λ·gae_{t+1}
  ret_t  = gae_t + V(s_t)
  ```

  代入可得（归纳）：

  ```
  ret_t = λ^{T−t}·R  +  (1−λ)·Σ_{k=t+1}^{T} λ^{k−t−1}·V(s_k)
  ```

  （验证 t=T−1：`ret = λR + (1−λ)V_T` ✓）

  即：**critic 的目标里，真正的终局 ADP `R` 只占权重 `λ^{T−t}`，剩下的 `1 − λ^{T−t}` 全是 critic 自己的 bootstrap。**

  对一个典型 20 步决策序列（λ=0.95）：`0.95^20 ≈ 0.358` —— **终端 ADP 只有 36% 的权重，64% 是 Critic 自举**。越靠近开局，ADP 的份额越小。

- **算法危害**:
  1. `train.cpp:8` 的注释 "pure terminal ADP reward (paper aligned)" 以及 README 里"终局 ADP 收益目标"的表述，**在默认 λ=0.95 下是数学上不成立的**。只有在 `--lambda 1.0` 时才退化为真正的纯 MC（此时 `adv_t = R − V(s_t)`，与 README 的说法一致）。
  2. 更重要的是：这意味着**在没有 Oracle 中间奖励的前提下，信用分配完全依赖 Critic 沿着轨迹自己一步步做差分**。也就是 N1.6 里我说的、即便不信论文也成立的那个结构性损失：**Critic 必须先把 V 学准，策略才拿得到有意义的逐步优势**；在此之前，所有决策点拿到的几乎都是同一个 `R − V` 方向的近似，等于没有时间尺度上的区分度。
- **改进建议**: 至少修正注释/README（明确说明 λ=0.95 是 TD(λ) 目标而非纯 ADP）；如果确实想要"纯 ADP"，就跑 `--lambda 1.0`，或者引入 Composer 说的 Oracle 差分奖励把非零 reward 铺到逐步。

### N3 【P2，我认为对训练初期影响不小】Critic 输出头没有像 Actor 那样做零初始化

- **涉及代码**: `src/nn/net.cpp:335-336`（Actor 做了），`src/nn/net.cpp:443`（Critic 没做）
- **问题描述**:

  `Actor::init` 在最后显式把输出层清零，这是一个很好、很有意识的选择——初始策略在合法动作上**严格均匀**，熵最大：

  ```cpp
  head.init(c.hidden * 2, 1, rng);
  std::fill(head.W.w.begin(), head.W.w.end(), 0.0f);
  std::fill(head.b.w.begin(), head.b.w.end(), 0.0f);
  ```

  而 `Critic::init` 的输出层是 He 随机初始化：

  ```cpp
  out.init(c.hidden, 1, rng);       // net.cpp:443 —— 没有紧随的 std::fill
  ```

  所以初始 Critic 的输出是**随机、非零、尺度约 O(1)** 的数值。

- **算法危害**: 初始 GAE 会变成 `adv_t = R − V(s_t)`（λ=1 情形），其中 `V(s_t)` 是纯随机噪声，幅度与 ADP 本身同量级。也就是说：
  1. 训练最开始若干轮，Actor 收到的 advantage 方向**大体是随机的**（注意 `ppo.cpp:138` 的标准化只改变尺度、不改变方向），等于拿噪声做了若干轮策略更新；
  2. Critic 的 target `ret` 也带同样的随机偏置，Critic 自己要先花若干轮把这份噪声消化掉。

  这直接抵消了 Actor 零初始化的收益：**策略起点是最大熵的好起点，优势起点却是噪声。** 单独看不是致命问题（Critic 收敛快），但它确实让前若干轮 update 的采样被浪费，在 `--updates` 较小（默认 200）的短程训练里占比不低。
- **改进建议**: 复制 Actor 的做法，在 `Critic::init` 里把 `out` 的 W/b 清零。这样初始 `V ≡ 0`（不受上游随机层影响），初始 advantage 严格等于 ADP —— 这才是 `train.cpp:8` "pure terminal ADP" 想要的起点。同时建议把 `head`/`out` 的零初始化抽成一个共用函数，避免下次再写漏。

### N4 【P2】`clipVf` 以**陈旧**的 `vOld` 为中心，在 `--buffer > 1` / 联赛局里会误伤

- **涉及代码**: `src/algo/ppo.cpp:396`、`src/train.cpp:534`（`buf.cap`）、`src/train.cpp:667`（`live` pack 发布时机）
- **问题描述**:

  值裁剪的中心是 `float vOld = mb[i]->value`，即**采样那一刻的行为 Critic 的预测值**。这个 `value` 在两种情况下会是陈旧的：

  1. **流水线缓冲**：`--buffer N`（默认 1，可调大）允许生产者领先学习者 N 个 chunk，被消费的那份数据当时的 Critic 已经落后当前若干个 update；
  2. **联赛/历史席位**：虽然历史席位不写 transition，但同局里 Latest 席位的 transition 是跟着历史/规则智能体的行动轨迹走出来的，`V_old` 评估的是"最新策略对战最新约定国 Strangers"那条分布下的状态价值，而非纯自弈分布。

  一个围绕**陈旧中心**的绝对裁剪窗口，本质上是在说"不许偏离一个过时的估计超过 5.0"。当 Critic 因为学到了新东西而合理地想要大幅远离旧值时，这个窗口就会系统性地把梯度关掉（`ppo.cpp:401-403` 的 `dValue = 0`）。

- **算法危害**: 它与 Finding #2 / N1 是**乘性叠加**的：收益长尾 × 绝对阈值 × 陈旧中心，三者一起提高了"该更新的样本恰好被置零"的概率。
- **改进建议**: 修 N1（改相对阈值）即可自然缓解这一条；若想彻底规避，可以在消费 sample 时重算一遍 `V_old`（用当前 Critic 前向一次），把裁剪中心刷新到当前值——代价是一次额外的 critic forward，收益是 `clipVf` 重新变回"单步信任域"的语义。

### N5 【P3】`clipFraction` 统计口径偏大，会误导调参

- **涉及代码**: `src/algo/ppo.cpp:347-350`
- **问题描述**:

  ```cpp
  float rc = std::clamp(ratio, 1.0f - cfg.clip, 1.0f + cfg.clip);
  if (std::abs(ratio - 1.0f) > cfg.clip) {
      mbClipSum += 1.0f;      // 无条件计数
  }
  ```

  这在 `|ratio − 1| > clip` 时无条件 +1，**没有判断裁切是否真的改变了 surrogate**。PPO 里只有当 `sign(s)` 与被越界的那个方向一致时 `min(l1, l2)` 才会取到 `l2`（即真正被截断）。反方向时虽然 `ratio` 越界，`l1` 仍小于 `l2`，本没有被截断。

- **算法危害**: 日志里的 `cf`（`train.cpp:695`，README:109 明确把它列为"稳定指标"之一）会系统性偏高，可能让人以为"策略更新太激进"而错误地去调小 lr 或增大 clip。仅影响可观测性，不影响梯度。
- **改进建议**: 改成 `if ((s > 0 && ratio > 1 + clip) || (s < 0 && ratio < 1 - clip))` 才计数（这也和 `ppo.cpp:361-364` 里 `g` 的门控逻辑完全同构）。

### N6 【P3】动作没有规范化抽象（`abstractId` = 位置槽位），且 `Transition::mask` 是死字段

- **涉及代码**: `src/ddz/features.cpp:154`、`src/algo/rollout.h:25`
- **问题描述**:

  `LegalOption::abstractId` 取的是 **`out.size()`，即本次决策合法着法列表里的位置下标**，而不是任何规范的牌型编码：

  ```cpp
  o.abstractId = static_cast<int>(out.size());
  ```

  也就是说同一个"出 5"在第 3 环境和第 30 环境里会有不同的 id。这个设计在功能上是自洽的（每个 id 通过 `actionFeat` 带上了自己的 12×15 牌矩阵 + 6 个特征，网络是"逐个候选着法打分"，DouZero 式），**我不认为它是 bug**，但它有两个后果：

  1. **跨决策点零泛化**：同一个语义动作在不同局面下完全靠网络重新学习，没有共享的表征。这与 PerfectDou / DouZero 的设计一致，但如果有人想做"动作抽象版"是做不了的。
  2. **`kNumActions = 2048` 变成了硬上限**：`kNumActions` 必须 ≥ 单步最大候选着法数（`rollout.cpp:298-302` 有 `abort` 保护，`net.h:22` 的注释提到实测到过 519，最近一个 commit 正是为此扩到 2048）。建议把这个约束写成断言而非运行时的 `abort`。

  另外 `Transition::mask`（`rollout.h:25`，在 `rollout.cpp:237` 和 `eval_douzero.cpp:145` 被写）**从头到尾没有任何读方**——训练路径用的是 `-1e9f` 哨兵 + 全维 softmax。这是个死字段，建议删掉或改到 `assert` 路径上，以免后来者误以为 masking 是生效机制。

### N7 【P3】`vLoss` 的上报口径与 `vfCoef` 不一致（纯账务问题）

- **涉及代码**: `src/algo/ppo.cpp:402/405/409`（累加，未乘 `vfCoef`）vs `src/algo/ppo.cpp:406/410`（梯度，乘了 `vfCoef`）
- **问题描述**: 梯度是 `vfCoef · err / B`，但上报的 `vLossSum` 累加的是 `0.5·err²`，没有乘 `vfCoef`。
- **算法危害**: 无，不影响训练。只是日志里的 `vL`（`train.cpp:694`）数值与真实被优化的项差一个 0.5 因子，跨实验横向比较时（尤其改了 `--vf-coef` 之后）会困惑。

## 一、对前序多方审查观点的元评审与裁决 (Audit of Previous Reviews)

经过结合源码（`src/algo/*`, `src/nn/*`, `src/ddz/*`, `src/train.cpp`）的逐项对照推导，对前四轮报告的核心争议与补充意见裁决如下：

### 1. 关于「农民异质采样」的概率计算与严重性
- **争议焦点**: 异构率是 42%（Gemini / Copilot）还是 46%（CodeBuddy）？
- **源码裁决**: 
  - 设默认参数 `ruleProb=0.1, historicalProb=0.2, latestProb=0.7`。
  - 若仅统计「**一名农民为 Latest，另一名农民为非 Latest**」（即最新策略与异质队友共担 ADP 的局面），概率精确为：
    $$P = 2 \times 0.7 \times (0.1 + 0.2) = 0.42 \quad (42\%)$$
  - 若统计「**两名农民存在任意形式的异质组合**」（含历史快照配规则 Agent：$2 \times 0.2 \times 0.1 = 0.04$），全集概率精确为：
    $$P = 1 - (0.7^2 + 0.2^2 + 0.1^2) = 0.46 \quad (46\%)$$
  - 再加上 `rollout.cpp:216-225` 的 `anyLatest` 兜底（当全场无人抽到 Latest 时随机将一席强制篡改为 Latest），会进一步拆散同质农民。
- **最终裁决**: **确认全量异构率 46%、训练受害率 42%**。各方全票同意判定为 **P0 (Critical)**。此缺陷直接推翻了 `README.md` 中“单局保证农民策略一致性”的声明，破坏了 2v1 合作博弈的信用分配。

### 2. 关于「Value Loss Clipping (`vfClip=5.0`)」的影响定性
- **争议焦点**: 是“彻底锁死”还是“降低尾部样本效率”？
- **源码裁决**:
  - `ppo.cpp:401-403` 的 `l2 > l1 -> dValue = 0` 确实会将单步 Minibatch 的梯度置零。
  - 但多轮 Update 间，随着总体胜率迁移，rollout 阶段生成的 `vOld` 仍有上浮空间，因此并非“整个网络权重永久冻结”。
  - 然而，CodeBuddy 提出的 **N1 发现了更致命的隐患**：地主与农民的基础收益量纲为 **2:1**（地主 $\pm 2 \cdot 2^b$，农民 $\mp 1 \cdot 2^b$）。同一个绝对常数 `5.0`，地主 1~2 个炸弹即越界饱和，而农民需要 3 个炸弹才越界。**该常数对地主 Critic 的约束强度是对农民的 2 倍**！
- **最终裁决**: 采纳 Composer / Copilot / CodeBuddy 的修正。修正定性为 **P1 (High)**：虽非全局永久冻结，但严重扭曲高炸弹对局价值收敛，且对地主席位造成双倍负面抑制。

### 3. 关于「Oracle 中间密集奖励」缺失 (Composer Finding A)
- **争议焦点**: 是否算作 P0 缺陷？
- **源码裁决**:
  - PerfectDou (NeurIPS 2022) Sec 4.4 确实依赖 Stage 1 的 $Adv_t = N_{landlord} - \min(N_{p1}, N_{p2})$ 步进密集奖励，并在 Stage 2 转入纯 ADP 微调。
  - 当前代码仅实现了 Stage 2，且代码注释声称 `pure terminal ADP reward (paper aligned)`，在学术表述上存在偏差。
  - 但在 $\lambda=1.0, \gamma=1.0$ 下，基于蒙特卡洛全回报的强化学习算法在数学上自洽且具备收敛性（如 DouZero 原生设计）。
- **最终裁决**: 采纳 Copilot / CodeBuddy 意见，**定为 P1 (High) 的保真度与样本效率缺陷**，而非阻断训练的 P0 Bug。应先修正注释，并通过 ablation 实验确定引入 Oracle 奖励对训练加速的实际增益。

### 4. 关于 CodeBuddy 提出的全新发现 (N1 ~ N7) 裁决
- **N1（地主/农民 2:1 量纲与 vfClip 绝对值冲突）**: **完全成立，纳入 P1 核心结论**。
- **N2（$\lambda=0.95$ 下终局 ADP 权重仅 $\lambda^{T-t}$）**: **完全成立**。数学推导精确证明了在没有中间奖励时，越靠前的步骤越依赖 Critic 自身的 bootstrap（20 步时终局 ADP 权重仅剩 36%）。
- **N3（Critic 输出头未零初始化）**: **完全成立，纳入 P2 核心改进**。`Actor` 做了 `std::fill(0.0f)`，而 `Critic` 沿用 He 初始化，导致前几轮训练的优势估计叠加了大幅随机噪声。
- **N4（`clipVf` 以陈旧 `vOld` 为中心）**: **完全成立**，在异步流水线 `--buffer > 1` 时尤为严重。
- **N5（`clipFraction` 统计未做符号门控）**: **完全成立**，影响监控指标的真实度。
- **N6（`Transition::mask` 80 字节冗余死字段）**: **完全成立**。`rollout.h:25` 的 `mask` 仅写入从不读取，属于纯内存浪费。
- **N7（`vLoss` 上报口径未乘 `vfCoef`）**: **完全成立**，属于日志可解释性问题。

## 二、强化学习算法最终问题清单 (Unified Defect Matrix)

经过四轮交叉互审，当前 PerfectDouCPP 代码库的最终缺陷定级如下：

## 一、对 #5（Gemini 综合裁决）的审核

### 1.1 采纳项

D-01 / D-02 / D-03 / D-04 / D-05 / D-06 / D-09 / D-10 的结论我都复核过，成立。特别说明两点我特意自查过的：

### 1.2 【更正 1 · 重要】D-04b 的处方「用 `--lambda 1` 换回纯 ADP」是错的，请勿执行

#5 的 §二 D-04 与 #6 的缺陷表 D-04b 都写（#6 原文）：「默认 λ=0.95 时『纯终局 ADP』表述不实（N2）→ 若要纯 ADP 用 `--lambda 1`」。

这是我提出 N2 时**明确划开的界限**，但这条建议把它读反了。推导如下（γ=1，非终局 reward≡0）：

```
λ=1   :  ret_t = R                       → adv_t = R − V(s_t)
λ=0.95:  ret_t = λ^{T−t}·R + (1−λ)Σ_k λ^{k−t−1}·V(s_k)
```

**N2 讲的是 critic 的`ret`（目标值）里 ADP 的权重衰减，不是"λ 选错了"。** λ=0.95 是标准的 TD(λ) 偏差-方差折中，它本来就该让 critic 目标带 bootstrap —— 这正是 GA E 的设计目的。把它改成 λ=1 的后果是：

1. Critic 目标改用纯 MC 回报，**方差显著上升**（丢掉了 bootstrap 带来的方差削减）；
2. 而 Policy 侧 `adv_t = R − V(s_t)` 与 λ=0.95 版本相比，并没有获得更多"时间信用分配"——两种 λ 下每步的优势都由各自的 `V(s_t)` 做状态相关基线区分开了；λ=1 只是把 TD 差分那部分信息去掉了；
3. 结果是**通常更差的样本效率**，而不是更好的 ADP 保真度。

**正确的处置是**：把 N2 / D-04b 定性为**文档订正项（P2/P3 级别）** —— 把 `train.cpp:8` 的 "pure terminal ADP reward" 和 README 里的表述改成事实相符的说法（默认配置是 **TD(λ) 目标**，仅在 `--lambda 1` 时退化为 MC）。**λ=0.95 的默认值不需要动。** 真正想要逐步信用分配，唯一路径是 D-04 的 Oracle 差分奖励。

一句话：**N2 是"注释撒谎"，不是"超参错了"；别为了对齐注释去改超参。**

### 1.3 【更正 2】D-08 的"省内存"理由不成立

D-08 把 `Transition::mask` 定性为「80 字节冗余位掩码占用内存」。实际上每条 Transition 的真实体量是：

```
imp      = kImpBin = 39 × 180         = 7020 B   (features.h:32-33)
extra    = kExtraBin = 360 B
actions  = vector<pair<int, array<float,186>>>
           ≈ 748 B × 合法着法数(~50)  ≈ 37 KB    ← 真正的大头
mask     = array<uint64_t,10>         =   80 B
```

mask 占比 **< 0.2%**，删除它的内存/拷贝收益可以忽略不计。真正值得删的理由是我 N6 里说的另一条：**它是一个从不被引用的字段，会让人误以 masking 是生效机制**（实际生效的是 `-1e9f` 哨兵 + 全维 softmax）。建议把它提升到 `assert`/debug-only 或直接删，但工单里的"收益"应写成"消除误导"，不要写成"节省内存"——否则评审没法判断优先级。

### 1.4 【更正 3 · 对我自己的下修】N4 应从 P2 降到 P3

#6 在总评里对我的一条点评：「N4 在默认 `buffer=1` 时影响有限」。**这条质疑是对的，我要把 N4 往回拉一档。**

我复核后承认，N4 里我说"一次 update 内有 ≈12–20 次 Adam step，而 `vOld` 全程冻结"——**这部分恰恰就是标准 PPO 的定义**（`clipVf` 的 `vOld` 本来就是行为策略时刻的值，跨 epoch 不重算是 sb3/OpenAI baselines 的通行做法），不是缺陷。

N4 真正成立的部分只剩"跨 update 陈旧"： pipelines 里 `--buffer>1` 时 `t.value` 可能落后当前 critic 若干 update。而默认 `buffer=1` 时这个滞后约为 1 个 update，且 PPO 的 importance ratio 对 actor 侧已经做了修正（value 侧没做，但误差量级有限）。

**结论：N4 降为 P3**，归入 "#4 移到 D-02 一起处理即可" 的那一类，不单独作为 P2 主线。#5 把它排在 P2 是我给的信息过重所致，这里更正。

### 2.2 【补充 1】D-01 的修复是**训练样本量中性**的 —— 这条消除掉了改它的最大顾虑

没人算过这个。当前（独立采样）vs 修复后（阵营整体采样），**每局的期望 Latest 农民数完全相同**：

```
现在：E[#Latest 农民] = 0.7 + 0.7                      = 1.4
修复：E[#Latest 农民] = 0.7 × 2 + 0.2 × 0 + 0.1 × 0    = 1.4   ✓
地主席位：0.7 → 0.7                                    不变 ✓
```

**所以修复 D-01 不会削减农民的训练样本总量，也不会造成吞吐回退。** 唯一的分布变化是"至少有一个 Latest 农民"的**局占比**从 `1−0.3² = 91%` 降到 `70%`（每局贡献的 transfer 条数从混合 1~2 条变成同质 2 条），即局级覆盖变窄、局间方差略升，样本总数不变——这是可接受的代价。

补录还有 2.7%（`0.3³`）的局会触发 `anyLatest` 兜底，修复时按 #5 建议改成"整营切换"是对的。

### 2.3 【补充 2】D-04（Oracle 奖励）落地有个硬工程前提，两份裁决都跳过了

都说「在 `rollout.cpp` 里增加基于 `minSteps` 差分的单步奖励接口」就完事了，**但当前 rollout 的数据结构撑不住这件事**：

```cpp
std::array<std::vector<int>, 3> lastIdx;   // rollout.cpp:170 —— 每个座位每局只留 1 个下标
```

现在每个座位每局**只记住最后一条** transition 的下标，终局时一次性把 ADP 写进去（`rollout.cpp:359-367`，以及 hist/rule 两条路径的 438-446、472-480）。要写**逐步**奖励，必须改成"per-seat-per-game 的 transition 下标列表"，这是一个真实的结构改动（Copilot #3 的 Finding B 提过这点，但 #5/#6 的缺陷矩阵把它丢了）。

另外两个参数陷阱：

- **γ=1 下早期步会累积约 T 项差分奖励**，需要按论文的 `l` 系数（地主 −1.0×，农民 +0.5×）缩放，否则 ADP 会被杂鱼信号的量级淹没；
- 一旦 reward 变稠密，**`moves/g` 这个已观测指标的语义不变，但 ADP 的绝对值不再直接可比**，评测口径要重设基线。

### 2.4 【补充 3】比调 vfClip 常数更干净的替代方案：把 value loss 换成 Huber

D-02 的处置是"关掉 clipVf / 放大到 32 / 按角色分阈值"。这三条都能用，但都在给**一个有死区的损失函数打补丁**——`ppo.cpp:401-403` 那个 `dValue = 0` 的整样本弃用是问题的根源。

更好的做法是直接用 **Huber loss 训练 Critic**（参数 δ 按收益 RMS 设定，或对地主/农民用不同的 δ）：

- 保留了"大误差时限制梯度"的全部好处（这是 value clipping 想要的）；
- **没有零梯度死区** —— 大误差样本仍以固定斜率贡献梯度，不会因为一个几何巧合就把样本整体丢掉；
- 这是 Rainbow / IMPALA 系的标准做法，不需要 Infra "调参直觉"。

我的建议：把这条作为 **D-02 的首选方案**，#5 的三条作为"不想改损失函数时的退而求其次"。

### 2.5 【补充 4】第 0 步必须是"建立测量基线"，而不是先把 P0 改了

两份裁决都把"消融/评测"写在最后一行的括号里。**我认为它必须是第一步，理由是这个仓库已经有现成的裁判：**

- `src/eval_douzero.cpp` —— 对 DouZero-ADP 基线，**分 landlord / peasant 输出 WP 与 ADP**（`eval_douzero.cpp:270-278`），并落 CSV；
- `tools/eval_vs_douzero_loop.py` —— 边训练边定期评测 + 出趋势图。

所以落地顺序应该是：

1. **第 0 步**：用现有 ckpt 跑一次 eval vs DouZero-ADP，拿到 landlord ADP / peasant ADP / WP 的**基线数字**并存 CSV；
2. 之后**每次只改一个** D 项，`--updates` 固定、seed 固定，重跑并对比曲线；ΔADP 在噪声带内就不算修复。

否则改完 D-01 之后 WP 必然跳变（局占比从 91% 降到 70%、对手组成变了），没有基线就会把"分布重构带来的指标变化"误读成"策略变强/变弱"。

**同时提醒一个口径陷阱**（这条没人提过）：

```
training reward  : 农民 payoff = ∓1·mult        (game.cpp:83-84)
eval 报告的 ADP  : 农民 ours = -(±2·mult)       (eval_douzero.cpp:198-199，地主视角)
training 日志 ADP: ±2·mult                      (rollout.cpp:354-358 → train.cpp:681)
```

即：**训练日志那一行 ADP 与 eval 的 ADP 是同一个口径（地主视角 ±2·mult），可以直接比；但农民网络实际被优化的奖励只有它的 1/2。** 所以看到"农民 ADP 涨了但农民 rez 的规模小"时不要以为是 bug——这只是 N1 那个 2:1 量纲在指标侧的另一个投影。**跨系统比较指标前先对齐它们是按谁的视角算的。**

### 2.6 【补充 5】反对"封版"

#5 结语写「封版」。我同意 #6 的反驳，并补一句更硬的：

D-01~D-10 **没有一条**是被运行数据证明的。它们全部是静态分析 + 类比**得出的"应当会损害训练"的假设**。这里面至少 D-02/D-04/D-05 的最终收益大小、甚至 D-01 的实际伤害大小，都只有量级估计而没有实测。文件应该保持"可追加"状态，并在顶部标注：**本文件所有优先级均为静态评审结论，未经实测，以 eval vs DouZero-ADP 的对照数据为准。**

## 一、所有 AI 的核心共识汇总 (Core Consensus Across All AIs)

在历经 8 轮独立复核、数学推导与交叉质询后，全体评审 AI 达成了以下**完全一致的最终定论**：

1. **底层 PPO 算法数学实现完全可信，无需重写**：
   - 动作掩码下 Softmax 策略梯度 `probs[a] * (W - sumW)`、强制单一动作零梯度、LSTM 局部无状态展开（保证 Minibatch 随机打乱严格满足 IID）、Schulman $k_3$ 近似非负 KL 散度等核心推导，经多方独立推导验证完全正确。
2. **第一核心缺陷定级 P0：农民异质采样 (D-01)**：
   - 全量异构率 46%（直伤受害率 42%），两农民独立掷骰与 `anyLatest` 拆散队友，严重破坏双人协作信用分配，并与 README 承诺不符。必须按**阵营（Camp）**统一采样。
3. **第二核心缺陷定级 P1：Value Loss Clipping (D-02)**：
   - 绝对阈值 5.0 与斗地主指数炸弹长尾及地主/农民 2:1 收益量纲发生结构性冲突（对地主约束强度是对农民的 2 倍）。默认应通过 `--no-clip-vf` 关闭或放宽阈值。
4. **第三核心缺陷定级 P1：断点续训状态丢失 (D-03)**：
   - `--resume` 丢弃 Adam $m/v/t$、退火进度重置回峰值、清空联盟池，存在策略退化与震荡风险。应持久化优化器状态与训练步数。
5. **澄清关键纠偏 (D-04b)：保持 $\lambda=0.95$，严禁倒退为 $\lambda=1.0$**：
   - 采纳 CodeBuddy 与 Copilot 的纠偏：$\lambda=0.95$ 是标准的 TD($\lambda$) 偏差-方差折中，ADP 权重随时间衰减是 GAE 自举的正常数学特征。仅需修正注释中“纯终局 ADP”的误导性文案，**绝对不要为了对齐注释去改默认超参**。
6. **低成本高收益项定级 P2：Critic 输出层零初始化 (D-05)**：
   - `Actor` 显式清零实现最大熵，`Critic` 沿用 He 初始化引入了前若干轮优势估计的随机噪声。一行清零改动即可彻底解决。
7. **数据与可观测性升级 (D-06, D-08, D-09)**：
   - 日志拆分 pure self-play 与 league 对局指标；移除未使用的 80 字节 `Transition::mask` 冗余字段；修复 `clipFraction` 统计门控。

## 一、背景与问题追溯 (Context & Incident Background)

在前期显存泄漏修复后，系统曾发生两次严重事故：
1. **第 1907 步卡死 (Hang)**：多座位并发训练时，旧版 `syncLane` 依赖 Win32 `HANDLE` 事件与 `cuLaunchHostFunc` 回调。由于多个座位在 `cudaBridgeSyncAll()` 中共享并并发重置同一个事件句柄，导致完成信号丢失，线程永久阻塞在 `WaitForSingleObject(ev, INFINITE)`。
2. **第 2332 步权重崩溃为 NaN**：提交 `3c44288` 将等待改用原生的 `cuStreamSynchronize`，但引入了致命的竞态：`syncLane` 在流同步完成后重新上锁并强行将 `g_lanes[idx].busy = false`。当 0 号座位跨流同步 2 号 lane 时，2 号座位正好并发发射了新核函数并将 `busy = true`，0 号座位退出同步时把 2 号 lane 强行抹为 `false`；随后的读取提前返回、未等流执行完成，`cuMemcpyDtoH` 读回半成品/未计算完成的梯度，造成参数污染并在第 2332 步爆发 NaN。

## 二、Copilot 提交修改的逐项技术审查 (Review of Copilot's PR #3)

Copilot 在 PR #3 中针对 NaN、卡死和序列化健壮性提交了以下代码，我们进行了逐行交叉复核：

### 1. `src/algo/ppo.cpp`：生产者-消费者环形缓冲条件变量防丢唤醒
- **修改点**：将 `produced.store(tail + 1)`、`consumed.store(head + 1)` 以及 `stopProducer.store(true)` 的写操作包裹在 `std::lock_guard<std::mutex> lk(slotMu)` 内。
- **评审结论**：**通过且赞同**。虽然变量本身是 `std::atomic<size_t>`，但在调用 `slotCv.notify_one()` / `slotCv.notify_all()` 前持锁修改被等待谓词的状态，符合标准 C++ 多线程工程规范，彻底消除了由于重排序或上下文切换引发的伪丢失唤醒（Lost Wakeup）隐患。

### 2. `src/algo/ppo.cpp`：PPO Minibatch 样本级非有限值熔断与截断
- **修改点**：
  - 在计算策略比率前校验 `if (!std::isfinite(logRatio) || !std::isfinite(mb[i]->adv)) { nonFinite = true; continue; }`；
  - 增加硬截断：`logRatio = std::clamp(logRatio, -20.0f, 20.0f)`；
  - 在 Critic 价值损失前校验 `if (!std::isfinite(vPred) || !std::isfinite(vTarget)) { nonFinite = true; dValue.row(i)[0] = 0.0f; continue; }`；
  - 触发非有限样本时在 stderr 打印 `WARN: non-finite logits/values/targets in minibatch; samples skipped`。
- **评审结论**：**强烈赞同**。$e^{20} \approx 4.85 \times 10^8$，此截断范围既完全保留了正常 PPO 裁剪区间（$1 \pm 0.2$），又能有效遏制巨大策略差导致的浮点上溢。样本级单条跳过机制保证了就算极少数数据异常也不会使整批梯度污染。

### 3. `src/algo/rollout.cpp`：采样推断端 NaN 拦截与降级
- **修改点**：
  - `chooseAction` 中若 `!(sum > 0.0f) || !std::isfinite(sum)`，降级为从合法动作中均匀等概率采样，并返回合法 `logp = -std::log(float(opts.size()))`；
  - `runWorker` 中保存转移前校验 `tr[i].value = std::isfinite(values.row(i)[0]) ? values.row(i)[0] : 0.0f`。
- **评审结论**：**通过**。切断了脏数据从自对弈收集端逆向流入训练缓冲区的污染源，防止异常模型生成毒样本反噬后续迭代。

### 4. `src/nn/gemm_cuda_bridge.cpp`：资源释放与 Lane 索引修复
- **修改点**：
  - 在 `cudaBridgeDrop` 中，即使 `cudaBridgeSyncAll()` 返回失败，也强制继续清理 D3D 映射缓存（`cudaBridgeSyncAll();` 替代原本的提前 `return;`）；
  - 在 `cudaBridgeHasWork()` 中，将未分配 lane 时的默认查找由 `0` 改为 `laneIndex()`：`int idx = t_lane < 0 ? laneIndex() : t_lane;`。
- **评审结论**：**优秀修复**。
  - D3D 资源即将被底层释放，若因同步失败提前返回，会在 `g_maps` 中残留失效的虚拟地址映射，后续重用同一虚拟地址时会直接崩溃；
  - 未绑定线程调用 `laneIndex()` 能动态分配并绑定正确的 TLS lane，避免全部堆积在 0 号 lane 查询。

### 5. `src/nn/net.cpp`：优化器梯度范数校验与反序列化全或无原子性
- **修改点**：
  - `Adam::applyGradNorm` 增加 `if (!std::isfinite(norm)) { WARN; return; }`，梯度范数非有限时跳过步进；
  - `loadOptimizer` 改为先读取解析到临时变量 `tmp` 与局部向量 `ms`, `vs`，全部校验无误后一次性 `std::move` 生效。
- **评审结论**：**优秀工程实践**。保证了优化器文件在损坏或截断时完全保持原有内存状态（Atomic Rollback），不会留下半初始化脏权重。

本次双方 AI 的修复呈现出极佳的**互补性**，形成了两道坚实的防御体系：

```
                【第一道防线：硬件与驱动流并发层（Antigravity 实现）】

  • 分流锁层级 (g_laneMus[idx] -> g_mu)：

  • 主线程 180s 熔断看门狗 (waitLearners wait_for)：
    彻底消除无限期假死，死锁现场实时报警
                                      │
                                      ▼
                【第二道防线：算法与数据鲁棒层（Copilot 实现）】
                                      │
  • Rollout 端异常动作/价值保护：
    非法 logits 自动降级为合法均匀分布，阻断毒样本入库
  • PPO 更新端非有限样本熔断：
    logRatio 硬截断 [-20, 20]，单个坏样本置零跳过而非崩塌整批
  • 优化器梯度范数校验：
    非有限梯度直接跳过 Adam 更新，保全已有模型权重
  • 条件变量生产者-消费者同步强化：
    slotMu 锁内推进原子索引，彻底消除丢失唤醒
```
